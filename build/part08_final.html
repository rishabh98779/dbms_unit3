Comparisons most likely to be asked

ComparisonThe one discriminator to write first
Serial vs serializableSerial = no concurrency; serializable = concurrent but equivalent to some serial order.
Conflict vs view serializabilityConflict = swap non-conflicting operations / precedence graph; view = second type, not detailed in the source.
Recoverable vs cascadelessRecoverable allows dirty reads with delayed commit; cascadeless forbids reading uncommitted data at all.
Shared vs exclusive lockS = many readers, no writer; X = one transaction, read and write.
2PL vs strict 2PL2PL releases locks in a shrinking phase; strict 2PL releases everything only at commit (no cascading abort).
2PL vs timestamp2PL makes conflicting transactions wait (deadlock possible); TO aborts the younger one (no deadlock, but restarts).
Pessimistic vs optimisticCheck before each operation vs check once at validation.
Deferred vs immediate updateWrite at commit, no undo vs write at once, undo and redo both needed.
Procedure vs functionAction with no returned value vs calculation with mandatory RETURN.
Package spec vs bodyDeclares public interface vs implements it plus private items.

Before you close this PDF — traps flagged from the source

Check list
  • RAM is volatile, not non-volatile (the source's example list is wrong).
  • 2PL forbids acquiring a lock after any release — not the other way round.
  • In deferred mode, a crash before commit needs no undo.
  • Basic timestamp ordering is deadlock-free but not cascade-free / recoverable.
  • :OLD and :NEW do not exist for table-level triggers, and are null for INSERT/OLD rows on DELETE.
  • View serializability is only named in the source — no method is given.
