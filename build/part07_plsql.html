9§S09 Procedures & Functions source 3.1.1 – 3.1.2

Definition

Procedures and functions are PL/SQL subprograms: named blocks that are created and saved in the database as database objects, and can be called or referred to inside other blocks. A subprogram must be created manually; once created it is stored as an object.

Terminology

  • Parameter — a variable/placeholder of a valid PL/SQL datatype through which the subprogram exchanges values with the main code. Defined at creation, included in the calling statement, datatype must match the caller, and size is not specified at declaration (it is dynamic).
  • RETURN — transfers control from the subprogram back to the calling statement; code after RETURN is skipped. In a function it also returns a value whose datatype is declared at creation.

Procedure — characteristics

  • Standalone block stored in the database, called by its unique name.
  • Used to execute a process (not mainly to compute a value).
  • May contain nested blocks, and may be nested inside other blocks or packages.
  • Has an optional declaration part, an execution part, and an optional exception part.
  • Values pass in/out through parameters listed in the calling statement.
  • May contain RETURN to exit early but cannot return a value through RETURN.
  • Cannot be called directly from a SELECT statement; call from another block or with EXEC.

Function — characteristics

  • Standalone subprogram with a unique name, stored as a database object.
  • Used mainly for calculation.
  • Must return a value or raise an exception — RETURN is mandatory.
  • A function with no DML can be called directly in a SELECT query; a function with DML can only be called from other PL/SQL blocks.
  • May return a value through OUT parameters as well as through RETURN.
  • In a calling statement it is used with an assignment operator to receive the value.

Similarities

  • Both can be called from other PL/SQL blocks.
  • An unhandled exception propagates to the calling block.
  • Both can have any number of parameters and are database objects.

A subprogram is simply a procedure or function created on demand; once created it is stored as a database object.

Syntax and examples Must learn

CREATE OR REPLACE PROCEDURE name
( p1 IN/OUT datatype, ... )
{ IS | AS }
  declaration_part
BEGIN
  execution_part
EXCEPTION
  exception_part
END;
CREATE OR REPLACE FUNCTION name
( p1 IN/OUT datatype )
RETURN datatype
{ IS | AS }
  declaration_part
BEGIN
  execution_part
RETURN value;
END;

IS is used for a nested subprogram, AS for a standalone one — otherwise identical. OR REPLACE overwrites an existing version; the name must be unique.

CREATE OR REPLACE PROCEDURE welcome_msg
       (p_name IN VARCHAR2)
IS
BEGIN
  dbms_output.put_line('Welcome '||p_name);
END;
/
EXEC welcome_msg('Guru99');     -- Welcome Guru99

CREATE OR REPLACE FUNCTION welcome_msg_func
       (p_name IN VARCHAR2) RETURN VARCHAR2
IS
BEGIN
  RETURN ('Welcome '||p_name);
END;
/
-- call in a block, or directly in SQL:
SELECT welcome_msg_func('Guru99') FROM DUAL;

Execute a standalone procedure with EXECUTE name; or by naming it inside another PL/SQL block. Remove it with DROP PROCEDURE name;

Parameter modes Must learn

ModeUse and behaviour inside the subprogramWhat the caller may pass / how it is passed
IN
default		Input only. Acts like a constant — read-only, cannot be assigned.A constant, literal, initialized variable or expression (e.g. 5*8). Can have a default value. Passed by reference.
OUTOutput only. Acts like a variable — can be assigned and then read.Must be a variable. Passed by value.

Three ways to pass parameters

  • Positional: findMin(a, b, c) — first actual → first formal, and so on.
  • Named: findMin(x => a, y => b, z => c) — each actual is tied to a formal with =>.
  • Mixed: findMin(a, b, c, m => d) — legal only if positional parameters come first.
-- IN and OUT together
PROCEDURE findMin(x IN number, y IN number,
                   z OUT number) IS
BEGIN
  IF x < y THEN z := x; ELSE z := y; END IF;
END;
-- call: findMin(a, b, c);   → c = 23

-- IN OUT: same parameter in and out
PROCEDURE squareNum(x IN OUT number) IS
BEGIN  x := x * x;  END;
-- call: squareNum(a);       → a = 529

  • 2 marks: define procedure and function; which parameter mode is the default? what does RETURN do?
  • 5 marks: explain IN, OUT and IN OUT with one example each; write the syntax of a procedure.
  • 10 marks: “Differentiate procedures and functions with syntax and examples” or “Explain parameter modes and methods of passing parameters in PL/SQL”.
  • Likely questions: (i) Can a procedure be called from a SELECT statement? Why not? (ii) Explain positional, named and mixed notation. (iii) List the advantages of stored procedures.

Advantages and disadvantages of stored procedures Quick recall

Advantages: better performance (compiled once, cached executable); higher productivity (reuse); ease of use; scalability (processing isolated on the server); maintainability (one copy on the server); security (access only through procedures with definer's privileges).

Disadvantages: testing is difficult (data errors appear only at runtime); debugging is difficult or impossible in some databases; no version control; extra cost (a DBA/developer is needed); poor portability (complex procedures may not move to another database or a newer version).

10§S10 Triggers source 3.1.3

Definition — must learn

A trigger is a stored program that is automatically executed (fired) when a specified event occurs. Triggers can be defined on a table, view, schema or database.

Events that fire a trigger

  • DML: INSERT, UPDATE, DELETE.
  • DDL: CREATE, ALTER, DROP.
  • Database operations: SERVERERROR, LOGON, LOGOFF, STARTUP, SHUTDOWN.

Benefits (purposes)

  • Generate derived column values automatically.
  • Enforce referential integrity.
  • Event logging and storing information on table access.
  • Auditing; imposing security authorizations.
  • Synchronous replication of tables.
  • Preventing invalid transactions.

Anatomy of the CREATE TRIGGER statement

CREATE [OR REPLACE] TRIGGER trigger_name
{BEFORE | AFTER | INSTEAD OF}
{INSERT [OR] | UPDATE [OR] | DELETE} [OF col_name]
ON table_name
[REFERENCING OLD AS o NEW AS n]
[FOR EACH ROW]
WHEN (condition)
DECLARE ... BEGIN ... EXCEPTION ... END;
BEFORE / AFTERWhen the trigger body runs relative to the event.
INSTEAD OFUsed to create a trigger on a view.
FOR EACH ROWRow-level: fires once per affected row. Without it the trigger is table-level and fires once per statement.
WHENCondition selecting rows; valid only for row-level triggers.
:OLD / :NEWOld and new values of the row for INSERT/UPDATE/DELETE; not available in table-level triggers.

Worked example

CREATE OR REPLACE TRIGGER display_salary_changes
BEFORE DELETE OR INSERT OR UPDATE ON customers
FOR EACH ROW
WHEN (NEW.ID > 0)
DECLARE
  sal_diff number;
BEGIN
  sal_diff := :NEW.salary - :OLD.salary;
  dbms_output.put_line('Old salary: ' || :OLD.salary);
  dbms_output.put_line('New salary: ' || :NEW.salary);
  dbms_output.put_line('Difference: ' || sal_diff);
END;
/

Output and rules

ActionTrigger output
INSERT (new row, salary 7500)Old salary: null; New salary: 7500; difference null
UPDATE id=2, salary 1500→2000Old salary: 1500; New salary: 2000; difference: 500
  • OLD/NEW references work for row-level triggers only.
  • To query or modify the same table inside the trigger, use AFTER — only then is the table back in a consistent state.
  • A trigger may be written for one operation (BEFORE DELETE) or several.
Exam focus — Triggers
  • 2 marks: define trigger; list the three event categories; difference between row-level and table-level trigger.
  • 5 marks: write the syntax of a trigger and explain each clause; list any five benefits.
  • 10 marks: “What is a trigger? Explain its types, syntax and benefits with an example.” → definition, events, BEFORE/AFTER/INSTEAD OF, row vs statement, OLD/NEW rules, salary example with output.
  • Likely questions: (i) When would you use an INSTEAD OF trigger? (ii) Why are OLD and NEW unavailable in table-level triggers? (iii) Write a trigger to log salary changes.

11§S11 Packages & Cursors in Packages source 3.1.4 – 3.1.5

Definition — must learn

A package is a schema object that groups logically related PL/SQL types, items (variables, constants, exceptions, cursors) and subprograms. It has two parts: a specification (the interface) and a body (the implementation); the body is sometimes unnecessary.

SpecificationBody
Declares types, variables, constants, exceptions, cursors and subprograms visible outside.Contains the code of the declared subprograms plus private declarations hidden from outside.
Created with CREATE PACKAGE.Created with CREATE PACKAGE BODY.
Objects here are public.Subprograms coded here but not declared in the spec are private.

Access an element with package_name.element_name, e.g. cust_sal.find_sal(code).

CREATE OR REPLACE PACKAGE cust_sal AS
  PROCEDURE find_sal(c_id customers.id%TYPE);
END cust_sal;
/
CREATE OR REPLACE PACKAGE BODY cust_sal AS
  PROCEDURE find_sal(c_id customers.id%TYPE) IS
    c_sal customers.salary%TYPE;
  BEGIN
    SELECT salary INTO c_sal FROM customers
     WHERE id = c_id;
    dbms_output.put_line('Salary: '||c_sal);
  END find_sal;
END cust_sal;
/

Cursors inside a package

  • A cursor declared in the package specification or the global part of the body stays open until the end of the session once opened.
  • Therefore always test the cursor attribute %ISOPEN before referring to it.

Overloading

Having several subprograms with the same name that differ in the number of parameters, their types, or the return type. Used when many subprograms do the same task but must be called differently.

Dependencies to remember

  • The specification is a standalone object; the body depends on the specification.
  • Compiling the specification invalidates the body, which must be recompiled.
  • A subprogram that depends on a private element must be defined after that declaration.
  • Database objects referenced by the spec/body must be valid at compile time.

Advantages of packages Must learn

AdvantageExplanation
ModularityEncapsulates related types, items and subprograms in one named module; interfaces between packages are simple and clear.
Easier application designYou can code and compile the specification without the body; subprograms that reference the package can then be compiled. Bodies are written later.
Information hidingYou choose which items are public or private; changing a private implementation affects only the package, protecting integrity and simplifying maintenance.
Added functionalityPublic variables and cursors persist for the whole session and are shared by all subprograms; data can be kept across transactions without storing it in the database.
Better performanceThe whole package is loaded into memory on first call, so later calls need no disk I/O; packages stop cascading dependencies, so changing a body does not force recompilation of callers.
Exam focus — Packages
  • 2 marks: define package; name its two parts; what is a public vs private object?
  • 5 marks: write a package specification and body for a simple example and call one element.
  • 10 marks: “Explain PL/SQL packages with specification, body and advantages” or “What is overloading? Explain cursors in packages.”
  • Likely questions: (i) Why must %ISOPEN be checked for a packaged cursor? (ii) What happens to a package body when the specification is recompiled? (iii) List five advantages of packages.
