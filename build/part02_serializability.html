2§S02 Serializability source 3.2.3

Definition — must learn

A serializable schedule is a non-serial schedule of n transactions that is equivalent to some serial schedule of those same n transactions. It always leaves the database in a consistent state. Every serial schedule is trivially serializable; a non-serial schedule must be tested.

Serial vs serializable

PointSerial scheduleSerializable schedule
ConcurrencyNone; transactions run one after another.Allowed; transactions interleave.
UtilizationLower resource utilization and CPU throughput.Improves resource utilization and CPU throughput.
EfficiencyLess efficient.Always better than a serial schedule.

Two types

  1. Conflict serializability — checked by swapping non-conflicting operations (precedence graph).
  2. View serializability — named by the source as the second type.

Serializable schedules are always consistent, recoverable, cascadeless and strict.

Check this point The source lists view serializability but gives no definition or method. Do not invent one in the exam; write that it is the second type and that it is used where conflict serializability fails. Learn conflict serializability properly — that is the one fully explained.

Conflict serializability — method Must learn

A schedule is conflict serializable if it can be converted into a serial schedule by swapping non-conflicting operations.

Precedence (serialization) graph

Graph G = (V, E): one vertex per transaction; draw edge Ti → Tj when:

  • Ti writes Q before Tj reads Q  (W→R)
  • Ti reads Q before Tj writes Q  (R→W)
  • Ti writes Q before Tj writes Q  (W→W)

An edge means the first transaction must be executed before the second.

Four steps to answer an exam question

  1. List all conflicting operation pairs.
  2. Draw one node per transaction.
  3. Draw an edge Ti → Tj for each conflict pair.
  4. Check for a cycle: no cycle ⇒ conflict serializable; cycle ⇒ not serializable.

Topological sort of the resulting DAG gives the equivalent serial order(s); there may be more than one.

Exam focus — Serializability
  • 2 marks: define serializable schedule; define conflicting operations; what does a cycle in the precedence graph prove?
  • 5 marks: test a given schedule for conflict serializability using the four steps; write the equivalent serial order.
  • 10 marks: “Explain serializability. Differentiate serial and serializable schedules. Test the given schedule.” → definition, comparison table, conflict rules, graph with cycle/no-cycle conclusion.
  • Likely questions: (i) Test the schedule for conflict serializability. (ii) Define conflict and conflict serializability. (iii) Why is every serial schedule serializable but not the reverse?
